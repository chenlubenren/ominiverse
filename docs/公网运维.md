# Linux 公网运维示例

以下使用 `example.com`、独立用户 `spatial-sim` 和 `/opt/spatial-simulation` 示例目录。部署前替换域名，并按目标机器调整 Node.js、Blender、Certbot 的可执行文件路径。这里不包含生产服务器地址、账号凭据或证书。

## 安装运行版本

准备 Node.js 20+、Git LFS 和 nginx；需要生成新模型时另装 Blender。以下命令在有 sudo 权限的管理终端运行，将 `release_id` 设为本次版本的唯一目录名：

```bash
set -eu
release_id=release-001
release_app="/opt/spatial-simulation/releases/$release_id/app"
sudo useradd --system --user-group --home-dir /nonexistent --shell /usr/sbin/nologin spatial-sim
sudo install -d -m 0755 "/opt/spatial-simulation/releases/$release_id"
sudo git clone https://github.com/chenlubenren/ominiverse.git "$release_app"
sudo git -C "$release_app" lfs pull
cd "$release_app"
sudo npm ci --omit=dev
sudo install -d -o spatial-sim -g spatial-sim -m 0750 /opt/spatial-simulation/shared/runtime /opt/spatial-simulation/shared/cache
sudo ln -s /opt/spatial-simulation/shared/runtime "$release_app/.runtime"
sudo ln -s /opt/spatial-simulation/shared/cache "$release_app/.cache"
sudo ln -s "$release_app" /opt/spatial-simulation/current
```

已有服务用户、共享目录或 `current` 链接时，跳过相应首次初始化步骤，并使用下文的版本切换流程。保持应用代码由管理员拥有，服务用户仅写入所需数据目录。

查看 `deploy/spatial-simulation.service`，把 `ExecStart` 中 Node.js 路径及 `BLENDER_PATH` 改为实际安装位置。该示例只监听 `127.0.0.1:8910`，并限制服务用户对系统的写权限。可选秘密配置通过 `/etc/spatial-simulation.env` 提供，该文件采用 `NAME=value` 格式并限制为 root 可读（权限 `0600`）。

```bash
sudo install -m 0644 deploy/spatial-simulation.service /etc/systemd/system/spatial-simulation.service
sudo systemctl daemon-reload
sudo systemctl enable --now spatial-simulation.service
sudo systemctl status spatial-simulation.service --no-pager
curl -fsS http://127.0.0.1:8910/__access_lab_health__
```

## HTTPS 与反向代理

将自己的域名解析到服务器。`deploy/nginx-spatial.conf` 中所有 `example.com` 都需替换为实际域名，证书路径也须对应。

首次部署时，先用仅监听 80 端口的临时站点提供 `/.well-known/acme-challenge/`，根目录为 `/var/www/html`。通过自己安装的 Certbot 为实际域名签发证书，例如：

```bash
sudo certbot certonly --webroot -w /var/www/html -d example.com
```

证书存在后再启用完整 nginx 配置；没有证书时直接加载示例的 443 配置会失败。确认未与现有默认站点冲突，然后执行：

```bash
sudo install -m 0644 deploy/nginx-spatial.conf /etc/nginx/sites-available/spatial-simulation
sudo ln -s /etc/nginx/sites-available/spatial-simulation /etc/nginx/sites-enabled/spatial-simulation
sudo nginx -t
sudo systemctl reload nginx
```

示例将 HTTP 跳转到 HTTPS，保留路径和查询参数；代理保留 Host 及 API 路径，支持静态压缩和视频 Range 请求，并在公网隐藏健康接口。实际部署还需开放 80/443 端口。

Node.js 启动时会构建并预压缩首页脚本与样式包。代理须保留内容编码和缓存响应头，不能对已压缩响应再次压缩。HTML 每次验证更新；带内容哈希的代码与模型可长期缓存。更新代码、样式或首页后重启服务，使资源包与本次文件保持一致。

若系统安装的 Certbot 已带自动续期定时器，使用该定时器即可。仓库另提供 `spatial-certificate-renew.service` 和 `.timer`：使用前将其中 Certbot 路径改为本机路径，避免与已有定时器重复。安装后先执行 `certbot renew --dry-run`，再启用定时器。示例定时器每天按服务器时区检查两次，并添加随机延迟；续期成功后验证并重载 nginx。

## 可选 Linux 网络配置

`deploy/90-ominispace-network.conf` 只设置 TCP 拥塞控制为 BBR，不含服务器地址或凭据。它适用于内核提供 `tcp_bbr` 的 Linux 主机，可用于评估长距离或丢包链路的吞吐量。它是主机级可选配置，不是应用启动依赖，也不保证所有网络更快。

先记录原算法，再加载模块并确认可用：

```bash
sysctl net.ipv4.tcp_congestion_control
sudo modprobe tcp_bbr
sysctl net.ipv4.tcp_available_congestion_control
```

确认可用算法包含 `bbr` 后，可将配置安装到 `/etc/sysctl.d/90-ominispace-network.conf`，用 `sysctl -p` 应用该文件，并在 `/etc/modules-load.d/ominispace-bbr.conf` 中写入 `tcp_bbr` 使模块开机加载。保留现有网卡队列设置；容器或受限主机应由宿主机管理员配置。用新连接比较启用前后表现，并记录测试是否经过代理。需要撤销时，将该配置改回先前记录的算法并重新应用，同时撤销本次添加的模块自动加载设置。

## 检查与备份

```bash
sudo systemctl status spatial-simulation.service nginx --no-pager
sudo journalctl -u spatial-simulation.service -n 100 --no-pager
curl -fsS http://127.0.0.1:8910/__access_lab_health__
curl -fsSI https://example.com/
```

定期备份 `shared/runtime` 中的任务和模型，备份含有用户数据，应按私有数据保管。可安排任务空闲时短暂停机取得一致副本。缓存可以重建；证书和环境配置单独备份。不要把生成接口作为健康检查。

## 版本切换与回滚

新版本使用新的发布目录，完成 LFS 下载、依赖安装和检查，并链接同一份 `shared/runtime` 与 `shared/cache`。模型、清单、本地解码器和运行代码应作为同一版本发布。若通过硬链接复用旧版文件，替换前须断开待更新文件的硬链接，避免同时改变回滚版本。先记录旧目标：

```bash
readlink -f /opt/spatial-simulation/current
```

确认后台生成任务空闲后切换，`release_app` 必须指向已准备好的新版本：

```bash
set -eu
release_app=/opt/spatial-simulation/releases/release-002/app
test -f "$release_app/server.cjs"
test -f "$release_app/package-lock.json"
test -d "$release_app/node_modules"
test "$(readlink -f "$release_app/.runtime")" = /opt/spatial-simulation/shared/runtime
test "$(readlink -f "$release_app/.cache")" = /opt/spatial-simulation/shared/cache
sudo systemctl stop spatial-simulation.service
sudo ln -sfn "$release_app" /opt/spatial-simulation/current.next
sudo mv -Tf /opt/spatial-simulation/current.next /opt/spatial-simulation/current
sudo systemctl start spatial-simulation.service
curl -fsS http://127.0.0.1:8910/__access_lab_health__
```

随后检查公网页面、模型与核心交互。若需要回滚，将 `release_app` 改为刚才记录的已验证旧目录，再执行同样的停机、切换和启动步骤。只切换应用，不覆盖共享数据；涉及数据格式变更时，需先确认旧版可读取现有数据。服务单实例运行，避免滚动切换时同时启动两份进程。
