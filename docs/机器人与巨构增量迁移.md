# 机器人与巨构增量迁移

本轮把 `室内空间交互(1).zip` 的机器人库、实际造型生成、机器人叛变与损毁、巨构接触攻击和可选逐层传播演示接入当前项目。操作入口留在现有面板和聊天中，办公楼、园区、空间站继续使用本地界面与场景切换流程。小镇和猎杀营救模式未迁入。

迁移前已保存本地 Git 快照 `6398014`，并以 `d9d73bb` 补存最新空间站调整；本轮在 `codex/migrate-robot-increments` 分支进行。主界面布局以 `d9d73bb` 为对照。前端按钮、模型目录、服务提示、错误及第三方品牌名称使用通用文案；项目自己的名称 Ominispace 按用户要求保留在首页标题及页签。底层资源路径和接口标识保留兼容。

真实模型生成服务计费接口尚未验收；已验证的生成流程使用模拟上游，本地 Blender 绑定使用已有模板完成。已有模型部署和本地事件指令无需生成密钥。

## 打开机器人库

1. 进入办公楼或楼外园区，点击“部署具身智能”。
2. 在面板底部点击“机器人库与生成”。也可从聊天旁“事件实验”进入同名入口。
3. 选择小型、中型或大型，查看卡片的动作预览。模型库包含四种原生伙伴、八种扩展型号、五种巨构，以及收藏和已确认的生成模型。
4. 选择指定楼层或楼外入口、后方、左侧、右侧，再设置数量与行为，点击“调用到场景”。指定楼层可选 1–30F；园区中使用楼外位置。巨构只在楼外活动。

空间站仍使用原有专属机器人，地面机器人库不能把普通机器人或巨构部署进去。关闭窗口、复原或切场景时，尚未完成的部署会取消。已有模型和已确认入库记录继续保留。

## 区分已有模型部署与新外形生成

| 操作 | 结果 | 是否调用造型生成服务 |
| --- | --- | --- |
| 点击模型卡片“调用到场景” | 复制已有模型并设置位置、数量和行为 | 否 |
| 聊天输入“打造3个蓝色机器狗在11层乱走” | 解释类型、颜色、数量和行为，直接部署现有型号 | 否 |
| 按已入库名称调用，例如“调用2个我的机械鳄鱼在11层待命” | 复用对应生成模型及其动作 | 否 |
| “生成新3D模型” | 提交新外形、绑定骨架或关节、处理动作，预览后入库 | 是，需要自己的 Key |

已有的“打造自己的机器人”定制流程继续保留。新外形生成集中在独立的机器人库生成窗口，聊天中的“打造”本身不会静默提交计费造型任务。

生成新外形时，填写名字、尺寸和描述，再输入自己的模型生成服务 API Key。外形返回后先展示静态预览，可以旋转和缩放；骨架及动作完成后自动播放，只有通过校验才开放“确认并加入机器人库”。双足角色使用自动绑骨和动作配置；鳄鱼使用本地四足模板转移蒙皮；其他多关节造型走关节化流程。

如果连接中断或重启服务，重新打开窗口会查找同一浏览器的未完成任务。外形和任务编号保留后，可输入 Key 继续；确认过的模型可直接调用。关闭窗口会清空输入的 Key，不会终止已经提交的后台云任务。

服务器需要安装 Blender 和完整模板资源，支持通过 `BLENDER_PATH` 指定程序位置，详见[部署说明](部署.md)。默认会探测本机 Blender。生成结果受上游服务与造型适配能力影响；代码中的准备状态不等于真实上游已通过验收。

## 从聊天运行机器人事件

在办公楼或园区的现有聊天框输入指令，按 Enter 执行。“事件实验”中的示例按钮会先把文本放入聊天框，仍需按 Enter。

| 示例 | 作用 |
| --- | --- |
| `打造3个蓝色机器狗在11层乱走` | 在指定楼层部署并巡游 |
| `打造2台物流机器人在大楼后方待命` | 在指定室外区域部署，保持待命 |
| `15层生成3台机器狗，用激光攻击人类` | 运行已有进攻机器人实验 |
| `11层机器人叛变` | 切换该层现有机器人的阵营 |
| `解除全楼机器人叛变` | 解除叛变；已损毁机器人需“复原”恢复 |
| `生成2个飞龙机器人` | 在楼外加入已有飞龙巨构 |
| `攻击这栋楼` | 让巨构接近幕墙并攻击 |
| `停止攻击这栋楼` | 停止攻击并返回巡游 |
| `让章鱼爬上外墙` | 切换可攀附巨构的运动 |
| `复原` | 清理本轮事件并恢复场景 |

叛变机器人会寻找人类，正常机器人通过目击或告警介入并可沿楼梯跨层搜索。第一人称拳击可损伤、击毁机器人；机器人身上的货箱、书本和文件在失衡或损毁时掉落。配送与巡检任务原本已存在，本轮新增持物姿态、物品和零件掉落。

巨构的嘴、拳头、前足或触手需要实际接触幕墙才造成局部破坏。飞龙具备城市避障飞行、转弯升降和脱离幕墙后恢复巡航；章鱼通过支撑落点交替移动。人员会对机器人袭击和楼体受攻击作出避险反应。任意新生成模型具备自己的关节动画，不应等同于五类原生巨构的完整导航与攻击机制。

巨构显示沿用本地规则：它们位于楼外，从室内向外观察时仍可见；切到空间站、场景过渡或矩阵实验时隐藏。压缩包中进入室内即隐藏全部巨构的显示规则未覆盖本地行为。

## 主动选择逐层传播演示

在“事件实验”点击“逐层传播演示”，或直接在聊天输入该文本并按 Enter。

演示在每个有合格人员的楼层选一名初始携带者。携带者在本层走动、停下打喷嚏；其他人员吸入累积达到阈值后进入潜伏期，随后继续传播。统计按启动时每层人员集合计算，人员来访不会改变分母。“病毒空气存活”调整立即影响已有云团，过期云团停止贡献暴露；低于感染阈值的残余剂量会衰减清除。

这是主动选择的独立演示。普通“呼吸感染”继续使用当前少量初始感染者和日常办公计划，不强制全员离座。演示结束或复原后，仍健康且未被其他事件接管的人员恢复办公；不会把已经死亡、变异或进入应急行为的人员强行改回正常。

演示默认最多保留 1,200 个空气云团、显示 6,000 个粒子，并限制每次更新的路径搜索数量；实例配置的硬上限分别为 2,400 和 8,000。可见粒子只用于展示，感染由暴露模型决定。这是加速的虚构传播实验，数值不代表真实疾病预测。

## 本轮性能优化与等值验证

2026-11-19，性能调整只减少重复计算：货物姿态在最终绘制阶段计算一次；没有叛变、没有进攻机器人或暂停时跳过不需要的人群索引；空弹体、碎片和阴影实例不重复上传缓冲。巨构坐标查询只刷新所需关节与祖先，姿态提交和绘制仍更新完整骨架；触手求解复用临时向量。恢复活动或出现攻击时，感知索引立即重新建立。

本轮没有降低输出分辨率、采样倍率、模型精度、阴影、材质或反射质量，也没有减少默认人员及机器人数量。原有前端布局、三场景隔离和暂停语义继续保留；小镇与猎杀营救模式继续排除。

浏览器对照使用同一份本地资产及优化前源码快照，本机 Chrome、RTX 4070 Ti SUPER、1440×1000 画布、像素倍率 1，默认 36 台办公机器人就绪后测量。下表中的浏览器耗时来自同一总览场景，计时项可能嵌套，不能相加当作整帧耗时。

| 验证项 | 优化前 | 优化后 | 结论 |
| --- | ---: | ---: | --- |
| 默认机器人货物姿态计算 | 72 次/帧 | 36 次/帧 | 重复调用减半 |
| 货物姿态 CPU 耗时 | 0.681 ms/帧 | 0.364 ms/帧 | 该样本减少约 46.5% |
| 闲置冲突模块 CPU 耗时 | 0.091 ms/帧 | 0.024 ms/帧 | 跳过无攻击时的人群索引 |
| 空进攻机器人组更新 | 0.032 ms/帧 | 0.0048 ms/帧 | 跳过空组的人群扫描 |
| 五类巨构递归骨架刷新 | 2,867,788 次 | 2,175,902 次 | 同样 120 个模拟步减少 24.1% |
| 五类巨构动作 CPU 耗时 | 7.743 ms/步 | 7.420 ms/步 | 三轮均值减少约 4.2% |

巨构 CPU 对照每轮同时运行五种真实模型，以 0.05 秒步长推进 18 秒，共 360 步。每轮在 12 个时间点对所有世界矩阵、模型顶点、法线及接触日志进行逐字节校验，优化前后完全一致；每轮的 12 条接触记录也一致。骨架刷新次数另以每版本 120 步统计，不能与 360 步的 CPU 总量混用。证据见[巨构专项记录](../output/playwright/render-performance/giant-cpu.json)与[性能汇总](../output/playwright/render-performance/summary.json)。

完整场景测量覆盖办公楼总览、室内、两者的暂停状态、机器人库、三巨构巡游、园区、空间站总览及舱内，均未出现页面脚本错误。最终短测记录总览 58.4 FPS、室内 57.8 FPS、机器人库 54.8 FPS、三巨构巡游 54.6 FPS。不同轮次出现显卡频率及运行负载波动，因此这些数据只说明本机短时运行情况，本轮不宣称全场 FPS 提升。详见[优化前场景记录](../output/playwright/render-performance/before-ab.json)、[优化后场景记录](../output/playwright/render-performance/after-ab.json)和[最终短测](../output/playwright/render-performance/after-short.json)。

优化后已重跑 9 项巨构动作与生命周期回归、2 项机器人库待命/攻击联测，以及巨构指令协议测试，全部通过。新增坐标回归确认：即使尚未绘制下一帧，修改祖先位置或关节姿态后，接触点与坐标转换仍读取最新状态。真实浏览器再次通过五类幕墙接触破坏、实体碎片、固定触手不误伤、章鱼支撑与攀墙、停攻、暂停，以及保留相机的完整复原，见[真实接触报告](../output/playwright/megastructure-contact/report.json)。

## 维护与恢复

修改服务器或 Blender 配置后重启 Node.js；前端更新后刷新页面。机器人生成数据保存在 `.runtime/robot-library/`，部署时作为服务数据持久化，应用发布包不包含开发机缓存或密钥。

迁移保留本地场景隔离、异步生成取消、原有渲染循环和感知预算。新增传播模块不重复重建人群碰撞结构或记录步态。这些生命周期约束在后续合并时也应保留。
